Kivy/KivyMD Android crash + edge-to-edge: test report

Crash: a GPU-driver crash in a Kivy Fbo draw after a screen switch; trigger to be named by a 5-APK phone kit (all 5 pass on the emulator). Edge-to-edge: overlap at targetSdk 35/36 on Android 15, two fixes tested.

TESTS.md (every run in a table)

Root cause

PROVEN (from the reporter's own crash log, read privately, nothing copied): the app dies with a native crash inside the GPU driver while Kivy draws into an Fbo, right after a screen switch. It is not a Python error. INFERRED (not yet tested on the phone): what creates that Fbo. Candidates: an Fbo-based screen transition (Fade / Wipe; our A-7 v2 run shows Fade adds Fbos on every switch), KivyMD shadows (elevation -> BoxShadow, one Fbo each; A-6 shows shadows off removes them), or any Fbo. In the public controlP code the screen manager keeps KivyMD's default MDSharedAxisTransition (no Fbo in our runs) and only the home screen cards have elevation + shadow, so shadows are the leading suspect there. The 5-APK kit tells these apart on the real phone. Separate issue: the status-bar overlap appears only on Android 15+ at targetSdk 35+, so it is a heads-up for newer phones, not this crash.

Recommendations

Crash workaround: turn off elevation / shadows on the screens involved in the switch (controlP: views/home/home.kv lines 10-13), and if you set a transition yourself, avoid Fade / Wipe. With MDScreenManager pick an MD transition (MDSlideTransition, MDSwapTransition): a plain Kivy transition set at startup is replaced by MDSharedAxisTransition on the next frame. Then run the 5-APK kit and report which variants crash. Build: p4a develop, materialyoucolor==3.0.4 (p4a's recipe ships 2.0.10, too old for KivyMD master), plus materialshapes, pycairo and pillow (KivyMD master needs materialshapes>=0.3; p4a installs KivyMD without its dependencies). Overlap: on Android 15+ at targetSdk 35+ only. At targetSdk 36 pad the layout with the window insets (A-4); the opt-out resource works at targetSdk 35 (A-3) but Android 16 ignores it at 36.

How to use the 5-APK kit

Five small APKs, each adding one factor: 1 plain Kivy, 2 + one raw Fbo, 3 + Kivy BoxShadow, 4 KivyMD with shadows off, 5 KivyMD with shadows on. Download them from the build matrix run (artifacts need a GitHub login), install all 5, open each, tap START once and leave the phone alone for 30 s: it flips between two screens 20 times and shows DONE (variant N, 20/20). Report for each: CLOSED BEFORE START, CRASH DURING SWITCHES (with the last switch number seen) or NO CRASH, plus phone model and Android version. Reading: first crash at 3 (or at 5 with 4 clean) = BoxShadow; at 2 = any Fbo; at 1 = not Fbo; at 4 but not 3 = KivyMD widgets / transition; none = another factor in the app. All 5 passed the emulator gate (runs above), so a crash on the phone is the phone's, not the kit's.

Limits

The emulator renders with SwiftShader (software OpenGL ES 3.0), so it cannot show a GPU-driver crash: the gate proves the kit itself runs, not that the phone is fine. Emulator = Android 15 (API 35), pixel_6; the reporter's phone, OEM skin and driver differ. Android 16 behaviour (the opt-out being ignored at targetSdk 36) was not tested. The trigger of the crash is inferred until the kit results come back. A GitHub run does not reuse a local .buildozer folder, so stale local build state is not covered.
