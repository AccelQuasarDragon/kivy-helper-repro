controlP on Android: round 3, crash cause found

  • 1. THE BUG: KivyMD's M3 ripple creates its Fbo with Kivy's default shader, then swaps in the ripple shader via fbo.shader.fs (kivymd/uix/behaviors/ripple_behavior.py:701-702, master a00c10c). On a Pixel 5 (Adreno, Android 11) the app crashed in the GPU driver after a list-row ripple drew. In every crashing run it was the first ripple the app drew (the home card's ripple is off by default).
  • 2. THE FIX: give the shader to Fbo() when it is created, as kivy/kivy#8098 did for BoxShadow. Load the source first (ripple.glsl with the "$HEADER$ " prefix; the module's RIPPLE_FS_STRING is still None at that point), then: self.fbo = Fbo(size=[50] * 2, group="m3_ripple_behavior", fs=fs), and drop the later self.set_shader(self.fbo).
  • 3. THE RUNS (Pixel 5, Android 11, one run each; links in the table below): CRASH with the unmodified ripple (S0) and with the stencil off but the same late shader (T2). CLEAN with the Fbo created with fs= (T1), also on the icon buttons and switches of the app's other-devices screen (OD). S0 is an older build with shadows off; T1, T2 and OD are one build with shadows on.
  • NOT the stencil (T2): a ripple with no Stencil instructions but the late shader still crashed, 5 ms after it drew.
  • Workaround also works (W): ripples off on list items (W drew no ripple at all). Your per-class ripple_effect=False works on MenuItem and InputItem, but NOT on OtherDevicesView: it is a screen, so its buttons and switches keep their ripples.
  • Shadows are not needed: the crash happened with shadows off (S0) and earlier with shadows on (DL1). Your builds already had shadows off.
  • Limits: one run per variant; Pixel 5 = Adreno 620, your Mi 9T = Adreno 618 (same driver family, not the same GPU).

Pixel 5 (Adreno 620) runs: the KivyMD M3 ripple sets its shader after creating its Fbo. Passing the shader at creation stopped the crash; removing the stencil did not.

What crashes

The crash is in KivyMD's M3 ripple, not in your code and not in BoxShadow.

In KivyMD master (a00c10c), RectangularRippleBehavior and CircularRippleBehavior are aliases of the M3 classes, so list items, icon buttons and switches all use M3CommonRipple.

M3CommonRipple.init_fbos creates an Fbo, and set_shader then assigns shader.fs on it.

kivy/kivy#8098 found that this order breaks on Adreno GPUs, and fixed BoxShadow by passing fs= to Fbo() at creation.

On the Pixel 5 the app died a few ms after a ripple drew, inside libGLESv2_adreno.so, under Kivy's fbo / vbo code (S0).

Why other_devices still crashes for you

Your commit sets ripple_effect = False on MenuItem, InputItem and OtherDevicesView.

MenuItem and InputItem are list items, so it works there.

OtherDevicesView is an MDScreen, which has no ripple, so the line does nothing.

Its 10 MDIconButtons and 2 MDSwitch thumbs keep their M3 ripples, and the entry button in the bottom bar ripples too.

Two ways out: switch the ripple off for the whole app (one patch of M3CommonRipple), or use the T1 change (Fbo created with the shader), which keeps the ripple.

Limits

One run per variant, and no run of the unmodified ripple on the shadows-on build (the closest are DL1, an earlier shadows-on build that crashed twice, and T2); both crashing runs died on the first list-row tap, but a single clean run is still one run.

The Pixel 5 has an Adreno 620, your Mi 9T an Adreno 618: same driver family, not proof for the 618.

You reported the other-devices crash; we did not run the other-devices taps on the shipped build, so we did not reproduce that one ourselves.

The phone ran in Firebase Test Lab with scripted taps and a fake device, not your Pioneer.

Each phone run's screenshots and video are shown under its own block; every image and video was looked at before publishing (8 frames per video, not every second).

Known gaps

  1. No run of the unmodified ripple on the shadows-on build (T1's build). Closest: DL1 (earlier shadows-on build, crashed twice) and T2 (same build, crashed). Close it: one run of the shipped config on that build on a physical Pixel 5 in Google Firebase Test Lab (form inputs only).
  2. Is it list rows, or any first ripple? Every crash was the first ripple drawn, and no late-shader ripple has ever survived on the Pixel 5. Close it: tap the top-bar power button (its own ripple, no list) before a list row, same Firebase Test Lab run as gap 1.
  3. GPU coverage: only an Adreno 620 was tested; #1900 has Adreno 506 and 750, your Mi 9T an Adreno 618. Close it: the S0 and T1 APKs on a physical Snapdragon Samsung in Google Firebase Test Lab (form inputs only).
  4. The fix only ran as an app-side patch (T1, code-identical to the KivyMD diff on desktop), never as KivyMD itself. Close it: build with KivyMD from a branch carrying the diff, then one physical-phone run in Google Firebase Test Lab.
  5. tilt_behavior.py in KivyMD sets its shader the same late way and runs on Android; untested, follow-up.
